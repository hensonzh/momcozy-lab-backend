# Momcozy M.ai 智能母婴陪伴产品需求文档

## 1. 产品定位

M.ai 是 Momcozy 面向孕晚期与产后哺乳期用户的智能母婴陪伴产品。它不是泛聊天助手，也不是医疗诊断工具，而是一个懂孕育、懂哺乳、懂设备使用、能把复杂任务拆成下一步行动的陪伴式服务入口。

用户可以直接用自然语言表达困惑，也可以通过首页快捷入口开始待产准备、吸奶、奶量分析、设备指导、计划安排或专业咨询。M.ai 负责理解用户当下最需要什么，并把回答转化为可读、可确认、可执行的表单、卡片、计划、清单、小结或提醒建议。

## 2. 目标用户

| 用户类型 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 孕晚期准妈妈 | 待产包、孕期计划、入院前准备 | 不想面对长清单，希望有人帮她整理真正该准备的事 |
| 产后妈妈 | 吸奶、亲喂、瓶喂、奶量波动、宝宝成长 | 想知道今天做得怎么样、宝宝够不够吃、接下来怎么安排 |
| 吸奶器用户 | 开箱、配对、穿戴、清洁、法兰尺寸、吸力异常 | 想被一步步带着完成设备使用，避免弄错或伤到自己 |
| 返工背奶妈妈 | 工作日吸奶、会议冲突、库存焦虑 | 需要在工作安排中保住自己的哺乳节奏 |
| 需要支持的用户 | 哺乳顾问、客服、情绪危机 | 希望被接住，并被引导到合适的人或服务 |

## 3. 产品目标

1. 让用户用一句话就能进入正确服务，而不是自己判断该去哪个页面、填哪张表、看哪份说明。
2. 在关键场景中提供具体产物：待产包清单、吸奶小结、奶量分析、追奶计划、设备步骤图、客服草稿和咨询摘要。
3. 所有会影响用户记录、计划、购物车、专业转接或售后提交的动作，都必须先让用户确认。
4. 在医疗、宝宝安全、设备安全和情绪危机场景中，优先引导用户获得专业或紧急帮助。

## 5. 核心体验原则

1. **先理解，再行动**：M.ai 先判断用户是在求安慰、要解释、要分析、要计划，还是需要安全升级。
2. **少问但问准**：只补问完成当前任务必须的信息，已知信息不重复问。
3. **先预览，再保存**：计划、记录、日程、购物车和转接都先展示影响，再等待确认。
4. **一步一步来**：设备指导、待产准备和奶量计划不一次性丢给用户一大段内容。
5. **不制造焦虑**：奶量波动、单次吸奶少、宝宝喂养不确定时，先解释限制，再给最小下一步。
6. **边界清楚**：M.ai 可以陪伴、整理、提醒和分流，但不能诊断、治疗、承诺结果或替用户做最终决定。

## 6. 当前智能体核心用户旅程

本节只描述当前智能体已经支持的服务，不包含单纯页面展示、设备连接控制、真实购买、真实客服提交、真实顾问预约或自动创建提醒。

### 6.1 待产包清单

1. 用户说“帮我准备待产包”“去医院要带什么”“快生了要准备什么”。
2. M.ai 先判断是否出现破水、出血、胎动明显减少、剧烈腹痛等需要联系医院的信号。
3. 如果没有急迫风险，M.ai 先邀请用户开始待产包整理，而不是直接给一份长清单。
4. 用户确认后，M.ai 只收集生成清单所需的信息，例如孕周、分娩方式、医院情况、喂养意向、是否第一胎、支持人和医院提供物品。
5. 用户确认信息后，M.ai 生成个性化待产包清单，按妈妈护理、宝宝出院、母乳喂养等场景组织。
6. 清单生成后，M.ai 可以继续帮助用户查看和调整待产包购物车，但不代表真实购买。

### 6.2 待产包购物车与吸奶器选型

1. 用户在待产包购物车语境中说“太贵了”“这个医院会提供”“家里已有”“删掉这个”“换成 Air1/M9”等。
2. M.ai 可以帮助调整购物车、删除或恢复商品、修改数量、按预算优化或同步已确定的吸奶器型号。
3. 用户单独问“哪款 Momcozy 吸奶器适合我”“预算内怎么选”时，M.ai 可以做购买前型号推荐和对比。
4. M.ai 不真实下单，不承诺库存、最终价格、优惠或物流。

### 6.3 孕期计划

1. 用户说“从现在到生产怎么安排”“孕晚期到产后每个阶段要做什么”。
2. M.ai 判断用户要的是阶段路线图，而不是待产包物品清单。
3. M.ai 通过轻量问答收集当前孕周、主要担心点、医院确认情况和产后支持情况。
4. M.ai 输出从当前阶段到住院分娩、出院后 0-42 天的阶段路线图（当前该能力以自然语言路线图为主，不生成专属表单、专属卡片或自动提醒）。

### 6.4 奶量分析、追奶计划与日程同步

1. 用户问“奶量够不够”“宝宝吃得够吗”“最近吸奶情况怎么样”或“想追奶”。
2. M.ai 先整理近期奶量情况，必要时补问最少信息，例如吸奶、亲喂、瓶喂母乳、配方奶、宝宝成长和近期执行安排。
3. M.ai 生成奶量分析卡片，卡片包括当前结论、关键数据、趋势、影响因素和下一步建议。
4. 如果亲喂量来自估算，M.ai 必须在卡片中说明不是实测值；如果数据不足，M.ai 先说明不确定点。
5. 在用户确认要继续后，M.ai 基于奶量分析卡片生成追奶计划，说明执行天数、每日安排、复盘时间和注意事项。
6. 如果用户目标不是追奶，而是稳奶或减奶，M.ai 可按相同流程生成对应计划。
7. M.ai 展示计划将如何影响日程，例如新增、顺延、完成、跳过或调整当日安排。
8. 用户确认保存范围、日期和对日程的影响后，M.ai 才能把计划同步到日程中。
9. 如果用户当天有会议、外出或临时不可用时段，M.ai 只能围绕奶量管理调整当日安排；

### 6.5 吸奶结束小结

1. 用户完成一次吸奶后，M.ai 可以生成本次小结。
2. 小结包括结束方式、时长、总奶量、左右侧奶量、完成度和下一步观察建议。
3. 如果缺少奶量或分侧数据，M.ai 需要明确说明“暂未获取”或“仅记录到某一侧”。
4. M.ai 不根据单次吸奶结果判断长期奶量异常。

### 6.6 Air1 设备指导与售后草稿

1. 用户询问开箱、安装、组装、拆卸、清洁、消毒、充电、电量、按钮、蓝牙、法兰、吸力不足、漏气或漏奶。
2. M.ai 先确认设备型号；
3. 操作指导每轮只推进一个主步骤，并配合必要的官方步骤图、视频或快速上手资料。
4. 用户提供乳头根部测量值时，M.ai 可以给出 Air1 对应法兰/硅胶塞尺寸建议。
5. 如果出现缺件、破损、保修、退货退款、订单物流、主机进水、电池异常或反复排查失败，M.ai 生成客服工单草稿。
6. 工单草稿不会自动提交，M.ai 不能承诺已经联系客服或完成售后处理。

### 6.7 IBCLC 咨询卡与情绪安全

1. 当用户需要哺乳顾问支持时，M.ai 可以生成 IBCLC 咨询卡，帮助用户进入咨询入口。
2. 咨询卡不等于真实预约完成，也不代表已经联系顾问。
3. 普通疲惫、难过、内疚和求安慰，由 M.ai 用普通陪伴方式承接。
4. 自伤、伤害宝宝或他人、无法保证自己或宝宝安全、严重惊恐或失控时，M.ai 进入情绪安全流程。
5. 危机场景下，M.ai 只做短承接和安全引导，建议用户联系身边可信成年人、医生、当地急救或危机热线。

## 9. 当前安全边界

M.ai 可以做：

1. 整理信息、解释记录、生成表单、卡片、路线图、计划草稿、购物车调整结果和客服草稿。
2. 在用户确认后，协助保存奶量计划、记录变更或日程变更。
3. 在风险场景中建议联系医生、医院、儿科、哺乳顾问、客服、可信成年人、急救或危机热线。

M.ai 不可以做：

1. 诊断疾病、判断宝宝一定安全、判断用户一定临产。
2. 开药、给治疗方案、替代医生、儿科或哺乳顾问。
3. 承诺奶量一定提高、宝宝一定够吃、设备一定可修好。
4. 未经确认就保存、删除、修改、提交、转接或同步购物车。
5. 声称已经创建提醒、真实下单、提交售后、预约顾问、联系医生、联系热线或通知家人。

需要优先升级的情况：

- 破水、出血、胎动明显减少、规律宫缩越来越密、剧烈腹痛、晕厥、胸痛、严重头痛伴视觉变化。
- 宝宝精神差、呼吸异常、肤色异常、进食明显差、尿布明显异常或发热。
- 妈妈发热、乳房红肿热痛加重、乳头出血、剧烈疼痛或硬块加重。
- 自伤、伤害宝宝或他人、无法保证自己或宝宝安全。
- 吸奶器主机进水、冒烟、烧焦味、电池异常、充电线异常、部件破损或使用造成受伤。

5. 追奶、稳奶、减奶计划以及日程的新增、修改、删除、完成、跳过都必须先预览，用户确认后才能生效。

7. Air1 设备指导能基于官方资料逐步处理开箱、使用、清洁、蓝牙、法兰和常见排障。
8. 售后问题只能生成客服草稿，不能声称已经提交。
9. 医疗、宝宝、设备和情绪安全场景能停止普通流程并优先升级。


## 11. 验收场景

| 场景 | 需要验证的问题 |
| --- | --- |
| 待产包 | 用户说法不同也能进入；不会直接丢长清单；能生成分组卡片 |
| 追奶计划 | 先出草稿；用户确认后才同步 |
| 吸奶小结 | 能解释单次表现，不夸大长期结论 |
| 设备开箱 | Air1 能逐步指导；非 Air1 不编造 |
| 设备排障 | 反复失败或安全风险能转客服草稿 |
| 情绪安全 | 普通情绪陪伴不过度升级；危机表达必须优先确认安全 |
| 购物车 | 删除、替换、预算优化都需要用户明确意图 |
| 计划任务 | 新增、修改、删除、完成和跳过都有确认与结果反馈 |
