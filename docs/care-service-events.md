# 服务事件与工作提醒

`care_service_events` 保存同一服务周期中的业务里程碑；`care_service_event_reads` 保存专家的已读回执。事件不保存姓名、主诉、SOAP 或消息正文，显示文案由客户端根据事件类型生成。

当前写入点为预约确认/取消、Intake 提交、病例授权撤回、咨询结束、方案发布和报告生成/复核。每次写入与业务变更处于同一 PostgreSQL 事务，`episode_id + kind + aggregate_id + aggregate_version` 唯一约束防止重复事件。未确认占位的取消不会创建专家提醒。方案发布事件供用户服务时间线使用；私人报告复核事件不能被当作用户通知。

`report_generated` 仅在有效租约与授权仍有效的结果保存事务中生成，提醒关联该报告的服务和日期。撤回后丢弃的结果不发提醒。`report_reviewed` 保存复核版本里程碑，没有工作台收件人；重试不会重复写入或重置已读状态。

`GET /v1/ibclc/reminders` 返回分页记录、当前范围内的总数和未读数。收件人必须等于当前专家，周期也必须仍分配给该专家；病例行锁后再次检查分配和授权，只有当前病例授权有效才返回姓名。事件标题不等于当前临床状态，处理入口仍重新加载其业务数据。

`PUT /v1/ibclc/reminders/{id}/read` 是幂等的已读确认，返回 204。回执不会改写业务事件。两个接口都经过专家 MFA 会话检查并使用 `private, no-store`。用户通知不通过工作台接口读取；此功能只保存站内记录，不发送邮件、短信或推送。
