# 宝宝档案与照护记录

产品基线为「momcozy-lab 产品设计」的 Baby 首页及五类记录。宝宝的 UUID 是档案、照护记录、咨询资料和服务关联的共同身份；每次访问按登录用户及宝宝归属鉴权。

## 当前契约

- `/v1/babies`：读取与创建档案；`PUT /v1/babies/{id}` 使用 `expected_version` 编辑。创建必须携带 `Idempotency-Key`。返回 `private, no-store`。
- 档案仅包含姓名、出生日期、出生记录性别（`female/male/unspecified`）、喂养方式及版本/审计时间。月龄按日历推算；未登记资料不补演示值。
- `/v1/babies/{id}/records`：按 `start_date`（含）、`end_date`（不含）及 IANA `timezone` 查询，支持类别、分页。时间记录按区间重叠读取，跨午夜睡眠包含在相邻日期；未来日期不包含尚未结束的过去睡眠。
- 五类观察为喂养、睡眠、尿便、生长、发育。喂养与妈妈泌乳记录分离；亲喂时长不转换为摄入量，瓶喂未知奶量保留空值。
- 喂养、睡眠、尿便记录实际带时区时间；生长与发育保存实际日历日期及填写时区，不构造中午等虚拟测量时间。切换时区后日历日期不改变。
- 每个宝宝仅允许一条进行中的睡眠。生长为单指标记录，单位由指标决定；发育保存指定行为及 `observed/not_observed/unsure`，没有能力分数或诊断字段。
- `POST /records/batch` 将同一类别、日期、时区的一至三项生长/发育观察在一个事务中保存。相同幂等键重复请求返回同一组记录；不允许重复指标或项目。
- `GET /records/latest-growth` 按指标读取最后一条未删除的测量，不受首页曲线日期范围限制，保留每项各自的测量日期。
- 编辑使用 `expected_version`，删除使用 `If-Match`，恢复使用删除后的版本。删除为软删除；创建重试不会复活已删除记录。并发操作按用户、宝宝、记录锁定。

## 模型迁移与共享

迁移 `20260908_0013` 新建 `baby_records`；`20260908_0014` 将 `infant_profiles` 改名为 `baby_profiles`，保留 UUID 和所有外键关联，收敛性别枚举，增加喂养方式与版本；`20260909_0015` 完成旧预产期字段清理。

`birth_weight_kg` 和 `gestational_age_at_birth_days` 随旧档案字段删除，不推造测量记录；这两项历史事实不能通过降级恢复。旧 `/v1/profile/infants` 入口已移除。AI 档案工具与上下文同步收敛，不再从已删除的孕周字段推断早产状态。

咨询资料可选宝宝使用同一 `BabyProfileRead` DTO；已提交的资料仍是独立、不可变的咨询快照。报告来源读取该服务关联宝宝的记录，并验证相同所有者、有效档案、授权、记录版本和报告时间；不会混入同一用户的另一个宝宝。

## 验证与待办

隔离 PostgreSQL 测试覆盖归属隔离、跨时区日历日期、午夜睡眠、并发活动睡眠、档案版本冲突、幂等批量保存、删除恢复和报告选定宝宝来源。ASGI HTTP 测试覆盖真实依赖下的认证、请求头、私有响应及新旧路由边界。Flutter 从真实合成数据库响应导出的夹具读取档案和五类记录。

Baby 首页、记录表单、历史列表、WHO 曲线和旧 Flutter 档案入口已完成。此文档不代表临床内容审核或云端发布已经完成；两者均需独立验收。
