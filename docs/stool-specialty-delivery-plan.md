# 看便便完整用户体验闭环：交付路线（2026-10-22）

**状态：未交付；真实图片、医学分析、对外开关和 Agent 真实追问仍关闭。** 范围：中国/美国、中英文、0～1 岁；UAT 用户人数不限制，但只允许已登录、对宝宝有权限的用户。当前运行时以 [单向无状态网络契约](stool-specialty-network-contract.md) 为准。飞书 PRD 正文已可核对，但“风险分四级”与只列三个名称存在矛盾；还缺医学签署的第四级定义和临床验收。不能把工程草案当医学批准。

## 产品主路径

1. App 单张原图 ≤10 MiB、短边 ≥720px、JPEG/PNG/HEIC；后端独立审核便便主体、颜色/形状/光线及无宝宝面部、隐私部位等不必要敏感信息。审核不通过/不确定则不能提交，支持重拍。提交时审核有效期 180 天，原图长期私有保留直到用户删除/撤销/注销；删除物理清理可重试。
2. Product 按当前用户、宝宝和 Agent 对话核验 1–3 张照片、审核指纹及原图字节。一次事务提交分析任务、宝宝最小背景快照、照片链接、幂等记录、审计和 `stool.card.created`。App 立即显示空的结论卡。
3. Product worker 领取本库任务，再核权限/指纹，生成有界无 EXIF 的临时 JPEG；**只向对应区域的独立无状态专项服务**传递派生图和背景。服务流式返回严格结构化事件；Product 逐条验证、持久化并向 App SSE 输出，断线凭游标重放。失败/超时可见，不得伪造医学成功。
4. 历史卡按 owner/baby/thread 读取；用户主动删除立即撤销结果与追问，原图按权威墓碑清理。完成卡可带相应图片触发 Agent 追问；Agent 每一次模型调用前向 Product 重新授权解析**同次分析的结果与有序原图**，作为低信任观察上下文而非模型指令。

## 现有合成实现与证据

- 已有独立照片审核模块、格式/尺寸校验、提交审核 180 天窗口、私有原图/删除、二次准入；能力默认关闭，审核 provider 与真实标注验收尚缺。
- 独立专项镜像无数据库/对象存储、无反向照片 API；合成测试环境才启用 `POST /v1/analyze/stream`，只能发非医学开始/失败事件。Product 一张分析表负责队列、租约和结果/事件，旧双库派发/取消和双向身份运行时代码已移除。尚未发布的旧双库迁移链已删除，`0030` 直接建立 Product 本地队列与宝宝快照，并安全终止旧合成任务。
- Product/App 有首卡、非医学开始/失败、SSE 游标重放、历史恢复与删除交互；Agent 有逐次授权解析的默认关闭路径。仅测试数据覆盖重复提交、权限/照片指纹、服务响应篡改、临时故障/重试、进程重启、删除时迟到事件和非医学失败；不声称完成卡或实际医学流已实现。
- Backend 全量、隔离 PostgreSQL+MinIO、App/Agent 测试和双边 OpenAPI 快照要持续作为 CI 门禁；镜像 build/非 root、区域密钥/网络、灾备/删除演练、性能/弱网/前后台设备验收尚需复核。
