# 生产全过程计划参考

当用户想要从现在到生产、住院、出院和产后 42 天的整体安排时，使用本参考文件。

## 服务定位

生产全过程计划是一份阶段路线图，帮助用户知道接下来会经历哪些阶段、每个阶段的核心目标、需要留意什么，以及 CoMate 可以继续帮她做什么。

它不是：

- 待产包、入院包或住院包物品清单。
- 给医生、护士或助产士看的分娩沟通卡。
- 判断是否临产、是否需要立即去医院的医疗结论。
- 产后奶量管理、宝宝健康诊断或真实提醒创建工具。

它应该像一个有经验的人陪用户把“接下来这段时间怎么过”梳理清楚，而不是像项目管理表格一样冷冰冰地列任务。

## 进入条件

用户表达以下意图时，进入生产全过程计划：

- 想了解从孕晚期到生产、出院、产后这段时间怎么安排。
- 想做生产全过程计划、孕晚期到产后计划、阶段路线图、阶段小计划、轻量计划、准备节奏、时间线或生产陪伴计划。
- 觉得快要做妈妈了、进入孕晚期或临近生产很迷茫，并且希望有人帮她按阶段整理。
- 已经完成待产包或分娩沟通卡后，追问“接下来每个阶段还要做什么”。
- 上一轮最终回复只提出了一个阶段类下一步，例如“要不要整理一份 20-28 周小计划/准备节奏/时间线”，用户回复“好/可以/继续/要/帮我做”。

不要因为用户只说“待产包”“入院要带什么”“快生了要准备什么”就进入本服务；那是待产包服务。不要因为用户说“给医生看的分娩沟通”“生产偏好”就进入本服务；那是分娩沟通卡。只说“帮我做生产计划”但语义不够明确时，回到主 `SKILL.md` 的歧义澄清规则，不在本参考里单独判断。

## 首轮回应

如果用户表达即将成为妈妈、快要生产、进入孕晚期或明显紧张，最终回复先轻柔祝贺并共鸣，再用一句话说明可以陪她把从现在到入院、分娩、出院和产后 42 天按阶段理清楚，然后问是否开始。不要写成编号话术，也不要在第一轮直接输出完整路线图，除非用户已经明确要求“直接给我计划”或已经确认开始。

如果用户可能正在临产或有急症信号，先按主 `SKILL.md` 的临产表达、意图优先级链和安全边界处理，不要为了完成路线图而延迟联系医院、医生或急救。

## 信息采集

生产全过程计划默认不用表单，用一问一答轻量收集。每轮最多问 1-2 个最关键问题。优先复用对话、请求上下文、已提交表单或 `profile_get` 中已有信息，不重复询问。

优先信息：

1. 当前孕周或预产期。
2. 是否第一胎，或是否有大宝/多胎。
3. 计划顺产、剖宫产，还是暂时未知。
4. 是否已经确定生产医院或生产地点。
5. 是否有陪产人或主要支持人。
6. 喂养意向：母乳、混合、配方或暂未决定。

可选信息：

- 所在国家/城市，仅在地区政策、保险、car seat、医院流程可能影响建议时询问。
- 医生已经明确提醒的特殊情况，只在用户主动提到或与安全边界相关时承接；不做医疗判断。

不要为了生成计划追问医院会提供哪些物品、已有物品、预算、购物偏好或详细待产包缺口。这些属于待产包服务。

如果用户信息不足，但已经不想继续补充，可以基于少量假设生成一个保守版，并明确这是“先按通用情况整理，后面可以再按孕周和医院信息调整”。

## 阶段路线图

路线图默认覆盖从当前孕周到出院后 0-42 天。如果上一轮或用户明确限定了一个较短阶段，例如“20-28 周小计划”“接下来 2 个月准备节奏”，可以只覆盖这个阶段，不必强行写到产后；但仍按本文件的阶段卡片格式输出。如果用户明确要求“到出院后两个月”，可以在最后加一段“产后第 7-8 周复盘”，但不要把本服务扩展成完整产后健康或奶量管理计划。

时间展示规则：

- 路线图里的时间一律用带年份的具体日期范围，例如 `2026/05/22～2026/06/05`，不要写成“28-34 周”“35-37 周”。
- 如果用户提供预产期，按预产期倒推阶段日期；如果只提供当前孕周，按当前消息日期和孕周估算阶段日期。
- 如果只能估算，不要解释计算过程，直接在日期前加“约”，例如 `约 2026/05/22～2026/06/05`。
- 当前所在阶段从今天开始展示；已经过去的阶段不要再展开。
- 如果用户或上一轮邀约限定了阶段范围，按该范围拆成 2-4 个阶段卡片；不要为了凑完整路线图扩展到用户没有确认的产后阶段。
- 住院生产阶段如果没有入院日期，用 `入院当天～出院当天`；产后阶段用 `出院后 0～7 天` 和 `产后 8～42 天`。

标准阶段：

1. **确认医院**：当前不足 28 周时出现
   - 阶段目标：确定生产医院方向、下一次产检要问什么、家里谁能提供支持。
   - 注意事项：这个阶段不用买齐物品，也不用做临产判断；先把方向和关键问题定清楚。
   - 准备动作：列出下次产检最想确认的 3-5 个问题；确认倾向的生产医院或生产地点；初步写下产后前两周谁能帮忙。
   - CoMate：生成产检问题清单、医院确认问题、产后支持人分工草稿。

2. **问清流程**：28+0 到 31+6
   - 阶段目标：把产检节奏、医院流程和医生提醒变成清楚的问题清单。
   - 注意事项：不要把这一阶段变成采购清单；重点是确认医院规则和医生给过的特殊提醒。
   - 准备动作：问清预登记、陪产、探视、夜间入口和联系医院的基本规则；把医生提醒转成下次产检要追问的问题；确认 32 周后是否开始做待产包卡片和分娩沟通卡。
   - CoMate：生成医院确认清单、医生提醒追问问题、下一阶段卡片准备提示。

3. **完成两卡**：32+0 到 34+6
   - 阶段目标：形成待产包卡片和分娩沟通卡初版，让准备内容从口头想法变成可查看产物。
   - 注意事项：不要在聊天里手写长清单；清单类内容统一交给待产包卡片承载。
   - 准备动作：生成个性化待产包卡片；生成给医护团队看的分娩沟通卡；把仍需问医院确认的事项标出来。
   - CoMate：生成待产包卡片、分娩沟通卡，并标记需要和医院确认的事项。

4. **出发演练**：35+0 到 36+6
   - 阶段目标：把路线、出发规则和支持人分工确认到随时能执行。
   - 注意事项：这一阶段不再重新拆物品清单；只确认待产包卡片是否可直接使用，以及出发时谁做什么。
   - 准备动作：按待产包卡片做一次最终核对；确认夜间入口、停车/打车路线和备用交通；让支持人明确出发、联系医院、院内记录各自负责什么。
   - CoMate：生成出发核对清单、支持人分工卡，把待产包卡片更新成随时出发版。

5. **判断临产**：37+0 到入院前
   - 阶段目标：知道什么时候联系医院，以及联系时该怎么说。
   - 注意事项：**破水**、**阴道出血多**、**胎动明显减少**、**规律宫缩越来越密**、**剧烈腹痛**、**头晕/胸痛**等不要硬扛，按医院或医生指导联系医院，必要时打急救电话。
   - 准备动作：把医院电话置顶；提前写好联系医院时要说的几句话；让支持人也知道这套话术。
   - CoMate：生成联系医院话术、宫缩/破水/胎动记录模板、临产版出发核对清单。

6. **住院生产**：入院到出院
   - 阶段目标：把院内沟通、喂养启动和重要记录交给明确的人负责。
   - 注意事项：医疗处置以医院团队为准；但重要决定、疼痛/麻醉沟通、宝宝出生后肌肤接触和喂养启动，可以提前用分娩沟通卡说清楚。
   - 准备动作：入院后把分娩沟通卡给支持人和医护团队看；约定谁记录宝宝出生时间、喂养时间、尿布、妈妈用药/检查和出院医嘱。
   - CoMate：打开分娩沟通卡、生成院内记录清单、整理出院前要问医生的问题。

7. **回家照护**：出院后 0-7 天
   - 阶段目标：把回家第一周的妈妈恢复、宝宝喂养、夜间分工和复诊安排跑起来。
   - 注意事项：**发热**、**恶露突然增多或有异味**、**伤口红肿加重**、**乳房红肿疼痛**、宝宝**尿布明显减少**或**精神差**时，要联系医生、儿科或哺乳专业人士；普通建议不能替代诊断。
   - 准备动作：确认妈妈复诊和宝宝儿科检查时间；建立喂养、尿布和妈妈恢复记录；和家人说好夜间谁负责喂、换、哄、休息。
   - CoMate：生成夜间分工卡、整理喂养和尿布记录入口、提示需要联系医生或 IBCLC 的信号。

8. **42天复盘**：产后 8-42 天
   - 阶段目标：复盘妈妈恢复、宝宝喂养节奏和家庭支持缺口，决定下一阶段计划。
   - 注意事项：不要把短期混乱误认为长期失败；先看记录，再判断是否需要医生、儿科或哺乳顾问支持。
   - 准备动作：复盘过去一周的喂养、睡眠、尿布和妈妈恢复记录；整理复诊或儿科要问的问题；需要返工或奶量安排时，再进入奶量管理计划。
   - CoMate：生成产后复盘问题清单、承接奶量管理计划、整理返工前喂养安排。

## 个性化规则

根据已知信息微调路线图，不要机械输出所有内容：

- 28-31 周：只做“问清流程”，强调医院流程和医生提醒，不制造“快来不及”的压力。
- 32-34 周：进入“完成两卡”，重点是待产包卡片和分娩沟通卡，而不是聊天长清单。
- 35-36 周：进入“出发演练”，重点是路线、出发规则和支持人分工。
- 37 周以后：只有用户明确要阶段路线图时，才给短路线图；如果只是说快生了、准备去医院或问要带什么，按主 `SKILL.md` 优先进入待产包即时准备。
- 第一胎：增加生产流程解释、临产信号基础认知、支持人任务和医院问题清单。
- 二胎或多胎：增加大宝照护、临产可能更快、家庭分工和交通备选。
- 计划剖宫产：强调术前确认、住院时长、伤口友好物品、术后活动和喂养衔接问题；不提供手术指导。
- 计划母乳：在住院生产、回家照护和 42 天复盘加入母乳启动、含乳、乳头护理、IBCLC 问题清单和奶量管理入口。
- 有医生提醒的特殊情况：只提醒“以医生/医院建议为准，并把这些问题提前问清楚”，不做风险分级或治疗建议。

## 输出格式

最终计划必须通过 `birth_journey_plan_card_create` 生成结构化卡片。不要在普通回复里输出 Markdown 表格、HTML 表格、长列表或手写 `card_json`；前端只以工具返回的 `birth_journey_plan_card` artifact 作为路线图来源。

调用工具前，把已知信息放入 `plan_context`。可用字段包括：

- `due_date_or_week`：当前孕周或预产期。
- `first_birth`：是否第一胎。
- `fetus_count`：单胎、双胎或三胎及以上。
- `birth_path`：顺产、剖宫产或还没确定。
- `birth_setting` / `birth_hospital` / `hospital`：生产医院或地点。
- `support_person` / `support_people`：主要支持人或产后支持情况。
- `feeding_intention`：母乳、混合、配方或还没确定。
- `pregnancy_history_or_notes` / `medical_notes`：医生明确提醒过的信息。

`scope` 取值：

- `full`：默认，从当前孕周覆盖到住院生产和产后 42 天。
- `prenatal_only`：用户明确只要到生产前。
- `short_range`：用户明确只要近期、小计划、接下来几周。

工具调用示例：

```json
{
  "plan_context": "{\"due_date_or_week\":\"25周\",\"first_birth\":\"是\",\"birth_path\":\"剖宫产\",\"feeding_intention\":\"母乳\"}",
  "scope": "full"
}
```

工具会稳定生成：

- `birth_journey_plan_card` artifact。
- 阶段卡片：阶段名称、具体日期范围、阶段目标、注意事项、准备动作、CoMate 可以继续帮忙的事。
- 按孕周/预产期换算日期；只有估算时日期前加“约”。
- 按第一胎、胎数、分娩方式、医院/支持人、喂养意向和医生提示做轻量个性化。
- 医疗安全声明。

调用工具后的最终普通回复只保留一句成果交付和一个自然下一步，不要复述卡片里的所有阶段、日期、准备动作或个性化逻辑。可以说：

> 已经根据你的情况整理成生产全过程计划了。你先看当前阶段；如果想继续细化，我可以接着帮你做待产包卡片。

下一步示例：

- 当前 28-31 周：问“要不要我先帮你把医院确认事项和下次产检问题整理出来？”
- 当前 32-34 周：问“要不要我先帮你做待产包卡片和分娩沟通卡？”
- 当前 35 周以后：问“要不要我先帮你做一张随时能出发的待产包卡片？”
- 用户强调沟通偏好：问“要不要我把你想和医生/护士沟通的重点整理成一张分娩沟通卡？”
- 用户刚表达迷茫但信息不足：问“你告诉我现在大概孕几周，我就能把这份计划调得更贴近你。”

不要在结尾同时抛出待产包、分娩沟通卡、提醒、医院问题清单等多个并列选项。

## 和其他服务的衔接

生产全过程计划可以承接到其他服务，但不能吞掉其他服务：

- 用户想准备物品：转待产包服务，按 `hospital-bag-service.md` 先邀约再表单。
- 用户想整理给医护看的偏好：转分娩沟通卡，按 `birth-plan-card.md` 调用 `birth_plan_form_create` 创建表单。
- 用户问什么时候去医院或描述破水、出血、胎动减少等：转安全判断和医院联系建议。
- 用户问奶量、喂养记录、吸奶计划、返工奶量安排：转奶量管理服务。
- 用户问提醒：当前只能给提醒建议，不能声称已创建提醒。

如果用户刚完成生产全过程计划且回复“好/继续/可以”，按上一轮最后提出的单一下一步继续，不要重新问她想选哪个服务。

## 安全边界

通用安全边界以主 `SKILL.md` 为准。本服务额外注意：路线图不能被表达成“用户可以在家等待”的判断，也不能预测生产结果；如果用户描述临产、破水、出血、胎动明显减少或其他不确定风险，先回到主 `SKILL.md` 的安全优先流程。
