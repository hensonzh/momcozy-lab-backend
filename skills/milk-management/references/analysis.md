# 奶量分析

这个 reference 用来回答“现在奶量和宝宝摄入是什么情况”。它只做分析，不生成计划，不保存计划，不写记录或日程。

## 什么时候用

- 用户问奶量够不够、最近怎么样、是不是偏低/偏高、宝宝有没有吃够。
- 用户要看最近吸奶、亲喂、瓶喂、奶粉、宝宝生长或计划执行趋势。
- 用户从奶量提醒进入，想知道为什么提示奶量偏低。

## 怎么做

1. 普通概念或单条记录解释，可以直接答。
2. 需要看数据时，先用 `tool_search` 加载 `milk_management` namespace。
3. 默认用 `milk_assessment_evaluate` 看近 7 天奶量、趋势、参考区间、记录完整度和下一步。
4. 如果涉及宝宝是否吃够、尿布/精神/体重、妈妈乳房不适，或是否适合追奶/稳奶/减奶，用 `milk_clinical_assessment_evaluate`。
5. 如果只是在查记录，用 `milk_records_query`；它只能说明“记录是什么”，不要单独拿它判断是否正常。
6. 如果用户问宝宝体重、生长或摄入是否足够，用 `infant_growth_evaluate`。

信息不够时，按这次判断需要追问。优先问会改变结论的信息，比如宝宝近 24 小时尿布和精神、妈妈有没有发热/红肿/硬块/疼痛加重、是否有漏记记录。

## 数据口径

不要把这些数据混在一起说：

- **计划任务**：来自 calendar，表示原本安排了几次、完成了几次。
- **有奶量的吸奶记录**：来自 pumping log，适合计算实测吸奶量。
- **记录与补录总数**：包含吸奶、亲喂、瓶喂等，不等于吸奶次数。

如果三类数据不一致，要直接说清楚口径差异。不要把“有奶量记录数”说成完整吸奶计划，也不要把“记录总条数”说成吸奶次数。

## 必看信息

分析时不要只看次数。至少看这些：

- 参考奶量区间。
- 实测吸奶量，以及亲喂估算量。
- 频次和排乳节奏。
- 连续几天偏低/偏高，还是只是一两天波动。
- 记录是否完整，尤其是亲喂、手挤、其它吸奶器或线下记录有没有漏记。

亲喂奶量如果来自估算，要说明是估算，不当作实测值。

## 回复方式

如果工具已经生成奶量分析卡，卡片就是主要结果。最终文本不要复述卡片内容，只引导下一步：

```markdown
我把近期奶量情况看完了。先别急着责怪自己，我们先把记录和节奏一项项顺清楚。

如果这些记录已经完整，我可以接着陪你做一份追奶/稳奶/减奶计划；如果你担心有漏记，我们先补齐再判断。
```

如果没有生成卡片，按这个顺序短一点说：

1. 当前结论。
2. 关键依据。
3. 最值得继续确认的影响点。
4. 下一步。

奶量偏低或记录不完整时，下一步优先确认是否有漏记。用户确认记录完整后，再进入追奶/稳奶/减奶计划。

## 不要做

- 不要下诊断。
- 不要直接生成或保存计划。
- 不要把工具字段、计算过程或每日明细全部倒给用户。
- 不要因为用户补充“没有红肿/没有硬块/主要吸奶时疼”就自动切成独立健康咨询；除非用户明确改问症状处理、用药、就医或宝宝明显异常。
