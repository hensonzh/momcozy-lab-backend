# 分析

本 reference 用于回答“现在是什么情况”。它不是独立服务，不生成追奶、稳奶、减奶计划，不保存计划，不写入记录或 calendar。

## 适用场景

- 用户问“奶量够不够”“最近怎么样”“是不是偏低/偏高”“宝宝是不是吃不饱”“要不要转奶粉”。
- 用户要求看近期奶量、吸奶、亲喂、母乳瓶喂、奶粉瓶喂、宝宝生长、计划执行或整体趋势。
- 前端卡片或状态页已经展示信息，用户继续追问原因、风险或下一步。
- 工具、日报或日程中出现连续波动、记录不足、执行不足或宝宝摄入/生长信号不清楚。

不适用：

- 用户只想知道今天怎么做：读取 `advice-now.md`。
- 用户已经明确要追奶、稳奶或减奶计划：读取 `advice-plan.md`。
- 用户明确要查、补、改、删记录或日程：读取 `execution-and-records.md`。
- 出现需要暂停普通奶量流程的情况：停止分析流程，回到 `SKILL.md` 的“暂停普通奶量流程的情况”处理。

## 分析顺序

### 1. 先判断是否需要工具

- 普通概念解释、轻量担心或单条记录解释，可以直接回答。
- 用户要求“帮我看看数据/分析最近情况/是否正常/够不够/趋势/风险/适合什么计划”时，再加载 `milk_management` namespace。
- 不要把一次记录查询自动扩展成综合评估，也不要把一次评估自动扩展成计划。

### 2. 选择数据来源

需要工具时，先通过 `tool_search` 加载 `milk_management` namespace。

- 当前状态、今日数据、30 日趋势、宝宝生长和任务概览：`milk_status_query`。
- 指定时间段的吸奶、亲喂、母乳瓶喂、奶粉瓶喂明细：`milk_records_query`。它只回答“记录是什么/每天多少”，不能单独用于判断是否正常。
- 用户要求分析近期吸奶/奶量趋势，或问“是否正常、够不够、偏低/偏高、是否需要计划、适合什么计划”：`milk_assessment_evaluate`。
- 用户问“最近吸奶情况”，且前端计划页或用户提到“任务、计划、记录与补录、完成了几次”时，优先使用 `milk_assessment_evaluate.data.calendar_task_summary`；如果需要展开具体时间，再读取 `milk_records_query` 和 `milk_calendar_query(query_mode="range")`。
- 用户提到宝宝体重、增长、发育、尿布、精神状态或摄入是否足够：`infant_growth_evaluate`。

### 2.1 区分数据口径

不要把下面三类数据混成一句“吸奶次数”：

- **计划任务**：来自 `calendar`，表示计划页安排了几次、完成了几次。
- **有奶量的吸奶记录**：来自 `pumping_log`，通常是设备或手动补录，适合用于计算实测吸奶总量。
- **记录与补录总条数**：来自 `pumping_log + feeding_log`，包含吸奶、亲喂、瓶喂等，不等于吸奶次数。

如果 `milk_assessment_evaluate` 返回了 `calendar_task_summary`：

- 说“吸奶节奏、计划执行、今天/这几天安排了几次”时，优先使用 `calendar_task_summary.completed_pump_task_count`、`average_completed_pump_tasks_per_day` 或 `daily[].completed_pump_task_count`。
- 说“实测吸奶量、有奶量记录、吸出来多少 ml”时，使用 `pumping_summary` 和 `milk_normality.days[].pumping_ml_total`。
- 说“记录与补录”时，使用 `pumping_summary.count + feeding_summary.count`，并说明它包含吸奶、亲喂、瓶喂等记录。
- 不要把 `pumping_summary.count / window_days` 直接说成“每天吸奶次数”；它只是“有奶量的吸奶记录数”。
- 除非用户明确问执行率，否则不要把 `calendar_task_summary.completed_pump_task_count` 单独包装成“真实完成次数”。如果它和有奶量记录不一致，要说“计划页标记完成”和“有奶量记录”是两层数据。

如果三者不一致，要直接解释口径差异，例如：

“计划页这几天每天有 8 个吸奶提醒，计划页都标记完成；记录与补录里每天有 10 条数据，其中 5 条是带奶量的吸奶记录，另外包含亲喂和瓶喂。实测吸奶总量按 5 条带奶量记录来算，记录与补录总数不能直接当成吸奶次数。”

### 3. 必看指标

做奶量分析时，不要只看“次数稳定”和“日总量波动”。必须同时看：

- **参考奶量区间**：优先使用 `milk_assessment_evaluate.data.milk_normality.days[].yield_reference.p15/p85`；如果用 `milk_status_query(trend)`，使用 `reference_lower/reference_upper`。
- **实际/估算奶量**：有亲喂估算时看 `estimated_daily_milk_ml` 或 `total_milk_estimate`，并说明亲喂部分是估算；没有亲喂估算时看实测吸奶总量。
- **频次参考**：看 `estimated_frequency` 与 `frequency_reference`，不要只说“每天几次很稳定”。
- **连续性**：看连续几天低于 P15、高于 P85，还是只是一两天波动。

### 4. 判断当前状态

只说明当前信号和不确定性，不诊断。

可归为：

- **记录补充中**：关键记录不足，先补齐记录或确认线下记录。
- **继续观察中**：在参考区间内有波动，但不足以直接进入计划。
- **需要关注**：连续低于 P15、高于 P85、执行率不足，或与用户目标不一致。
- **需要专业评估**：宝宝生长、尿布、精神状态或乳房症状提示专业评估优先。

### 5. 标准输出结构

分析近期吸奶或奶量趋势时，默认按下面 5 个小节输出。不要加“最近吸奶情况”这类大标题；直接从结论开始。小节标题保持稳定，内容保持短，不做一次性大段展开。

如果工具已经生成 `milk_analysis_card`，卡片就是主要结果；最终文本只能引导用户做下一步选择，不再复述卡片里的结论、数据、趋势、参考区间、原因推测或建议。

卡片后的回复示例：

```markdown
你想下一步怎么做？我可以帮你生成一个从明天开始的温和追奶计划，或者先看看今天怎么安排更合适。
```

不要在卡片后输出“整体看/结果是/数据显示/这 7 天……”这类分析句。

1. **结论**
   - 用一句自然、温和的话说明整体判断，不要用“先说一句”“看起来不是你没努力”这类解释腔开场。
   - 好：“你最近吸奶节奏很稳定哦～不过从总量看，最近 7 天整体还是低于参考标准，需要稍微关注一下。”
   - 不好：“先说一句：你最近不是‘乱掉了’，吸奶节奏其实很稳定；只是从总量看……”

2. **关键数据**
   - 用短行呈现，适合前端渲染成指标 chips；不要写成一整段长说明。
   - 常规只保留 2-3 个关键数字：时间范围、日均总量、平均次数、是否低于/高于参考区间。
   - 如果数据口径不一致，可以多列 1-2 行先把口径说清楚。
   - 如果存在计划任务或记录与补录口径，数字必须标注来源，例如“计划任务”“有奶量的吸奶记录”“记录与补录总条数”。
   - 如果有亲喂估算，说明“含亲喂估算”；没有亲喂估算，就说“仅看实测吸奶量”。
   - 不展开每日明细，除非用户要求“展开看”。

3. **趋势**
   - 说明最近是稳定、下降、上升，还是波动。
   - 优先回答用户关心的“有没有变差/有没有改善”，不要先解释计算过程。

4. **影响点**
   - 只说 1-2 个最值得继续看的因素，例如排空程度、夜间/清晨间隔、记录完整性、亲喂漏记、宝宝体重/尿布信号。
   - 不要罗列所有可能原因。

5. **下一步**
   - 给一个最小可执行动作：今天先怎么做、是否补一条关键记录、是否要生成从明天开始的追奶/稳奶/减奶计划。
   - 不直接保存计划，不直接写 calendar。

默认格式示例：

```markdown
**结论**
你最近吸奶节奏很稳定哦～不过从总量看，最近 7 天整体还是低于参考标准，需要稍微关注一下。

**关键数据**
- 计划任务：近 7 天每天 8 个吸奶任务
- 记录与补录：每天约 10 条，包含吸奶、亲喂和瓶喂
- 有奶量的吸奶记录：近 7 天 35 条，平均每天 5 条，用于计算实测吸奶量
- 实测总量：约 3760 ml，日均约 537 ml
- 含亲喂估算：约 614-696 ml/天，仍低于参考下沿约 707 ml/天

**趋势**
没有看到明显一路下滑，更像是低位稳定，有小幅波动。

**影响点**
次数本身不算少，接下来更值得看每次排空程度、夜间/清晨间隔，以及亲喂有没有漏记。

**下一步**
今天先别猛加量。你要不要我按这个情况，做一个从明天开始的 7 天温和追奶计划？
```

### 6. 表达边界

- 不要把计算过程、每日明细、P15/P85、频次参考、亲喂估算等全部展开；除非用户追问“为什么/怎么算的/展开看”。
- 可以提示风险，但不要下诊断式结论。
- 不把工具 `summary`、`advice` 或内部字段原样抛给用户。
- 亲喂奶量如来自工具估算，必须说明是估算，不当作实测值。
- 如果工具给出了参考区间，结论里要明确比较，但只保留用户最需要的一组数字，例如“最近几天含亲喂估算后，整体仍低于同阶段参考下沿，所以不是单纯一两天小波动。”需要数字时再补一句“约 614-696 ml/天，参考下沿约 707 ml/天”。

## 分析后的下一步

- 用户想知道今天怎么做：读取 `advice-now.md`。
- 用户想做追奶、稳奶或减奶计划：读取 `advice-plan.md`。
- 用户需要补记录、查日程、完成任务或调整时间：读取 `execution-and-records.md`。
- 用户只是想确认状态：解释评估结果，给一个今天或近期观察点。
