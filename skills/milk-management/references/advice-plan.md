# 奶量计划

这个 reference 用来做追奶、稳奶、减奶计划。计划必须先预览，再让用户确认；确认前不要保存，也不要写入日程。

## 什么时候用

- 用户明确要追奶、稳奶、减奶或做奶量管理计划。
- 用户完成奶量分析后，同意继续制定计划。
- 用户问“我适合什么计划”“接下来应该追奶还是稳奶/减奶”。
- 用户要修改、保存或删除已有奶量计划。

## 怎么做

1. 先确认计划方向：追奶、稳奶还是减奶。
2. 如果用户目标不清楚，先问她现在更想增加、稳住还是逐步减少。
3. 需要数据时，用 `tool_search` 加载 `milk_management` namespace。
4. 计划前先看近期分析结果；如果同一轮已经有有效评估结果，继续沿用，不要重复评估。
5. 如果涉及宝宝摄入/生长、妈妈乳房不适，或工具提示不适合继续，按工具结果补信息、建议 IBCLC/医生支持，或者停在更轻的下一步。
6. 如果要修改已有计划，先用 `milk_plan_query` 读取原计划。
7. 调用 `milk_plan_preview` 生成计划草稿；它只预览，不写入。
8. 用户确认后，才调用 `milk_plan_mutate` 保存、更新或删除计划。

计划算法、默认目标、任务安排和校验结果都以工具返回为准。不要绕过工具手写完整计划。

## 计划生成后的回复

如果工具已经生成计划卡，卡片就是主要结果。最终文本不要复述卡片，只做两件事：

- 简短说明这份计划的核心方向。
- 问用户是否需要保存/同步到计划页，或是否要先调整。

示例：

```markdown
这份计划不是让你硬扛，而是帮你把接下来几天变得更有把握一点。

如果方向没问题，我可以帮你同步到计划页；也可以先照着你的作息，把时间再调顺一点。
```

保存成功后，要主动问近期日程：

```markdown
计划已经保存好了。你不用一下子把后面每一步都想清楚，我们先把方向稳住。

如果你这几天有会议、外出、旅行、上班或想多睡一段，我也可以继续陪你把时间顺一下。
```

## 保存前必须确认

保存前要让用户知道：

- 保存的是什么计划。
- 覆盖哪些日期。
- 会不会写入或调整计划页日程。
- 如果已有未来计划任务，是追加、替换，还是只保存不改日程。

用户只是说“好/可以/继续”，但上一轮还没说清楚影响范围时，不能当作保存确认。

## 修改和删除

- 修改已有计划：先读已有计划，再生成调整预览，确认后写入。
- 删除计划：先说明会删除计划本身，以及是否删除关联日程；确认后再删除。
- 用户要根据会议、外出、睡眠变化调整时间时，转 `execution-and-records.md`。

## 不要做

- 不承诺奶量一定增加、稳定或减少。
- 不把计划当成医疗评估。
- 不输出完整每日时间表，除非用户要求展开。
- 不在用户确认前保存计划或写入日程。
