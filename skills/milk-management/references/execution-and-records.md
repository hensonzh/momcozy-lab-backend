# 执行与记录

这个 reference 用来处理记录、任务和日程。它是奶量分析和计划的落地能力，不是独立服务。

## 什么时候用

- 用户要查、补、改、删吸奶、亲喂、瓶喂或奶粉记录。
- 用户要新增宝宝身高、体重、头围记录。
- 用户要查看今日安排、完成率、今日日结或一段时间内的计划执行情况。
- 用户要标记任务完成、取消完成或跳过。
- 用户有会议、外出、旅行、上班、睡眠变化等安排，希望调整奶量计划时间。

## 基本规则

- 需要工具时，先用 `tool_search` 加载 `milk_management` namespace。
- 查询可以直接做；写入、修改、删除、顺延、完成任务前必须先确认。
- calendar 表示“计划/安排”；真实吸奶和喂养记录表示“实际发生”。不要混用。
- 真实记录用 `milk_record_mutate`，不要用 calendar 工具代替。
- 宝宝生长记录用 `infant_growth_mutate`；如果用户问是否正常，转 `analysis.md`。
- 完成、取消完成或跳过任务，用 `milk_task_complete`，不要直接改 calendar 完成状态。

## 查记录或日程

- 查吸奶/喂养记录：用 `milk_records_query`。
- 查今天安排：用 `milk_calendar_query(query_mode="today_overview")`。
- 查今日日结：用 `milk_calendar_query(query_mode="today_summary")`。
- 查一段时间日程：用 `milk_calendar_query(query_mode="range")`。

回复只保留用户需要的摘要。不要展示工具 JSON、数据库字段或完整内部规则。

## 补录、修改、删除记录

1. 先明确记录类型：吸奶、亲喂、母乳瓶喂、奶粉瓶喂。
2. 新增记录至少要有时间；奶量或时长不明确时不要猜。
3. 修改或删除记录前，如果对象不明确，先查候选记录让用户确认。
4. 用户确认后再调用写入工具。
5. 不要用计划值代替真实奶量或真实时长。

## 根据其它日程调整奶量计划

适用：用户说有会议、外出、旅行、工作排班、通勤、睡觉等不可用时间，想调整吸奶/亲喂计划。

1. 先确认日期、开始时间、结束时间或持续时长，以及事项名称。
2. 如果用户只说“上午有会”“下午很忙”，先问具体时间，不调用工具。
3. 如果用户发图片，只提取和日程有关的信息；日期或时间不清楚时先问，不要猜。
4. 调用 `milk_calendar_reschedule_preview`，让用户先看到会怎么调。
5. 预览里必须包含用户新增的事项本身，以及因此移动的吸奶/亲喂任务。
6. 面向用户只说：识别到的不可用时间、要移动几条任务、调整前后时间、是否同步到计划页。
7. 用户确认后，再调用 `milk_calendar_mutate(operation="apply_reschedule")`。

如果用户只是新增一个事项并顺带调整冲突日程，用 `milk_calendar_change_preview` 预览，确认后再用 `milk_calendar_mutate(operation="apply_adjustment")` 写入。

写入后只给简短摘要，例如：

```markdown
已经把 9:00 的吸奶挪到 8:20，也把 9:00-10:30 的会议放进计划页了。
```

## 确认规则

只有上一轮已经说清楚即将影响的对象、日期、时间范围和结果时，用户的“确认/可以/好的/就这样/帮我改吧”才算确认。

如果还没定位具体条目、用户继续补充条件、用户只是说继续聊，不能写入。先复述将要影响的内容，再请用户确认。

## 不要做

- 用户没有给具体时间时，不要直接预览或写入。
- 用户确认前，不要调用写入工具。
- 不要丢掉预览工具返回的 proposal；写入时使用完整 proposal。
- 不要把吃饭、外出、会议这类生活事项只作为理由，它们也要作为自定义事项写入 calendar。
